## 1. 문제 정의 및 배경

제조 현장에는 서로 다른 방식으로 이상 신호가 발생한다 — 회전체(엔진 등)는 **진동/소음 신호**로,
생산라인 비전 검사는 **표면 프로파일 신호**로 나타난다. 이 프로젝트는 이 두 이종 신호를
하나의 AI Agent가 함께 모니터링하여, 개별 판단 → 종합 리포트 → 조치 제안까지 자동화하는 것을
목표로 한다.

핵심 메시지: **"서로 다른 두 공정 라인을 하나의 Agent가 감시한다."**

## 2. 데이터셋

### 2-1. Ford Engine (KAMP DATASET_SEQ=2)
- 출처: IEEE World Congress on Computational Intelligence 2008 경진대회 데이터 (자동차 서브시스템 진단)
- 형식: 1차원 시계열, 길이 500 (엔진 소음 측정값)
- 규모: Train 3,601개 / Test 1,320개
- 라벨: 이진 분류 (증상 있음/없음), 클래스 비율 균형적 (Train 기준 약 51:49)
- 파일: `FordA_TRAIN.arff`, `FordA_TEST.arff` (CSV 형태 내장)

### 2-2. Machine Vision (KAMP DATASET_SEQ=6)
- 형식: 2차 공정 좌/우 라인 표면 프로파일 측정값
- **학습용 가공 데이터 사용** (원본 81,920포인트+연속값 대신, 80포인트로 다운샘플링 + OK(1)/NG(0) 이진라벨로 가공된 버전)
  - Right 라인: 422 샘플 (양품 333 / 불량 90 → 불량 비율 약 21%)
  - Left 라인: 413 샘플 (양품 283 / 불량 131 → 불량 비율 약 32%)
- 파일: `2nd_process_right_data.csv`+`_label.json`, `2nd_process_left_data.csv`+`_label.json`
- 참고: 원본 폴더에 참고용 시각화 이미지(jpg, 320×256, jet 컬러맵)가 있으나 **열화상이 아니라 프로파일 시각화**이며, 모델 입력으로는 사용하지 않음 (수치 데이터가 원 신호)
- **클래스 불균형 대응 필요** (class weight 또는 오버샘플링)

## 3. 시스템 아키텍처 (Perceive → Reason → Act)

```
[Engine 진동신호] ──┐
                    ├─▶ [1D CNN 이상탐지 모델 ×2] ──▶ 판단결과(정상/이상 + 신뢰도)
[Vision 프로파일] ──┘                                        │
                                                              ▼
                                         [LLM Reasoning] : 두 라인 결과 종합
                                         - 이상 원인 추정 자연어 설명
                                         - 정비 우선순위 판단
                                                              │
                                                              ▼
                                         [Act] 정비 리포트 자동 생성
                                              + Tool Call (Slack/이메일 mock 알림)
```

- **Perceive**: 두 데이터셋 각각 1D CNN 기반 이상탐지/분류 모델 (구조 공유, 출력 레이어만 분리)
- **Reason**: 모델 출력(클래스+확률)을 LLM에 전달 → 종합 판단 및 근거 설명 생성
- **Act**: 판단 결과 기반 정비 리포트 자동 작성 + 알림 Tool Call (mock 가능)
- **Memory/Feedback**: 과거 판단 이력 로그 저장 → 리포트에 "최근 이상 발생 추이" 포함 (간단한 CSV/SQLite 로그로 구현)

## 4. 모델 설계

| 구분 | Engine (Ford) | Vision (좌/우) |
|---|---|---|
| 입력 | 500포인트 시계열 | 80포인트 프로파일 |
| 구조 | 1D CNN (Conv1D + BatchNorm + GAP) | 동일 구조, 입력 길이만 상이 |
| 출력 | 이진 (정상/이상) | 이진 (양품/불량) |
| 불균형 처리 | 불필요 (균형) | Class Weight 적용 |
| 프레임워크 | PyTorch | PyTorch |

두 모델은 동일한 백본 코드를 재사용하고 입력 길이·클래스 가중치만 다르게 설정 → 개발 공수 절감.

## 5. 개발 환경

- 모델 학습: **Google Colab + PyTorch** (무료 GPU)
- **로컬 실행 백업**: Colab 세션 끊김/시연 당일 네트워크 이슈 대비, 추론 파이프라인은 로컬(Anaconda)에서도 동작하도록 경량화하여 준비

- 에이전트 구성: 별도 프레임워크 없이 Python 함수 체이닝으로 직접 구현 (1인 개발 규모에 적합)
